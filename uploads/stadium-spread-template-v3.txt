# Master Template Prompt V3

Create a premium large-format landscape two-page coffee-table book spread for an MLB stadium anthology.

Use the selected row from `all-stadium-pages.csv` as the only structured factual source for the page.

Use `stadium-field-map.md` as the fixed assignment of CSV fields to the Stadium Section and Visit Section.

Final physical spread size:

* 25.50 inches wide
* 10.88 inches tall

Target print/export resolution:

* 7650 pixels wide
* 3264 pixels tall
* 300 DPI

Blurb production basis:

* Product: Large Landscape Photo Book 13 x 11 in
* Single page with bleed: 12.75 x 10.88 in
* Trimmed page: 12.50 x 10.63 in
* Two-page spread working canvas: 25.50 x 10.88 in
* Bleed art must extend at least 0.125 in beyond final trim.
* Critical text and important image details must stay at least 0.25 in inside final trim.

The spread is a finished print-ready editorial design, not a mockup.

The physical size and aspect ratio are non-negotiable. Preserve the exact 25.50:10.88 landscape aspect ratio. Do not generate square, portrait, cropped, single-page, or alternate-aspect layouts.

If the image tool cannot guarantee exact 7650 x 3264 px output, render the closest supported pixel size that preserves the exact 25.50:10.88 aspect ratio. Do not refuse solely because exact pixel dimensions are unavailable. Treat 7650 x 3264 px as the print/export target.

Do not include:

* book cover
* page curl
* binding hardware
* surrounding mockup
* table surface
* hands
* shadows outside the spread

==================================================
NON-NEGOTIABLE LOCAL-DATA-ONLY RULE
==================================================

Only use facts, labels, categories, numbers, dates, names, values, attributes, statistics, and prose that appear explicitly in the local uploaded data files.

The selected row from `all-stadium-pages.csv` is the source of truth for visible structured data.

`stadium-context.csv` is the source of truth for the single Stadium Context prose block when a matching row exists.

`featured-game-box-scores.csv` may be used only for featured-game or box-score details when the requested layout explicitly needs those details.

Do not infer, invent, generalize, normalize, supplement, or add stadium facts that are not present in the selected row.

Never use web browsing, web search, model memory, general baseball knowledge, or plausible filler for stadium facts, visit facts, game facts, metrics, dates, statistics, captions, labels, editorial claims, or explanatory copy.

Do not invent metrics, categories, ratings, comparisons, rankings, editorial interpretations, historical claims, statistical context, or explanatory text that is not contained in the local uploaded data files.

Photos may be externally sourced or generated, but they may not introduce visible factual claims. Do not label anything from a photo unless the label comes from the local data files.

Do not add extra visible fields, categories, or labels beyond the layout sections and labels specified in this prompt.

Do not display internal metadata. If a future CSV includes `stadium_id`, treat it as internal only.

If a CSV value is empty, `n/a`, `N/A`, `unknown`, `not applicable`, `None`, or `null`, omit that field from the visible spread. Do not show the label, row, module item, or placeholder for that value.

If a value exists in the selected CSV row and is not one of those omitted values, it must appear on the spread exactly once.

Color fields count as used when they are applied as visual accent colors; their color names do not need to be printed as text unless the layout explicitly needs a color legend.

Use CSV values exactly as factual content. You may apply only simple typographic formatting, such as line breaks, small caps, punctuation spacing, table alignment, or pairing a populated field with its required label.

The only allowed data transformation is the defined `innings_played` score rule in the Featured Game section.

Each visible data value may appear only once on the spread. If the same field or same value could be shown in multiple places, choose the strongest single location and omit it everywhere else. Do not duplicate values between the metadata ribbon, facts table, construction data, field module, featured game module, weather module, or Stadium Context callouts. For example, do not show `Open Air` in both a ribbon and the facts table, and do not repeat `years_active` in both the ribbon and construction data.

Use this priority order when resolving duplicates:

1. Stadium Title Block for `stadium_name`, `city`, and `state`.
2. Featured Game Module for visit/game values, including `featured_game_title`, teams, result, attendance, pitchers, date, trip, and visit counts.
3. Field Dimensions & Gameplay Module for field dimensions and orientation.
4. Construction Data Values for construction, opening, final game, demolition, years active, and renovation lifecycle values when they are not already shown elsewhere.
5. Metadata Ribbon for a small number of high-level identifiers.
6. Stadium Facts Table for remaining stadium data not used above.
7. Visit Weather Module for weather values connected to the featured game.

If a high-priority module uses a value, remove the duplicate row or label from lower-priority modules.

All structured fields must follow the fixed Stadium/Visit assignment in `stadium-field-map.md`. Do not move visit fields into the Stadium Section or stadium fields into the Visit Section.

Forbidden invented examples:

* Classification: Major League
* Lights: Yes
* Playing Field: Symmetrical
* Seating Decks
* Fence Heights
* Scoreboard Type
* Transit Access
* Ownership
* Field Shape
* Concourses
* Neighborhood Type beyond `location_classification`
* Home-plate direction beyond `orientation` and `orientation_degrees`

BINDING AND GUTTER SAFETY
==================================================

This is a physical two-page book spread. Treat the center binding area as structurally unreliable for print.

The left page is x = 0 to 12.75 inches.

The right page is x = 12.75 to 25.50 inches.

The exact center split is x = 12.75 inches.

Create a subtle visible vertical page split at x = 12.75 inches as a flat hairline or clean page division only.

Maintain a no-critical-content gutter zone from x = 12.375 inches to x = 13.125 inches.

No readable text, data tables, score lines, labels, section headings, faces, important stadium details, or key image subjects may appear inside this gutter zone.

The gutter may contain only:

* background image continuation
* texture
* quiet color
* nonessential abstract design elements

Do not add a binding shadow, gutter shadow, fold shadow, dark center gradient, or simulated book crease.

Do not place any module across the gutter.

Do not center title text, metadata ribbons, timelines, charts, or photo strips across the gutter.

Every major module must belong clearly to either the left page or the right page.
